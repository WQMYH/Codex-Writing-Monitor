# Writing Ops plan execution skill

Generated by `skillflow-plan-to-skill`, this is the operations manual for the approved
Writing Ops implementation plan. It routes project work but does not replace project
contracts or record current state.

REQUIRED SUB-SKILL: `skillflow-testing` for every executable behavior change;
`skillflow-reviewing` for an authorized review gate. Expect the repository's configured
machine gates to exist and propagate every non-zero result.

## Recovery protocol

1. Read `docs/IMPLEMENTATION_STATUS.md`, the latest applicable frozen ReviewResult,
   `git status --short --branch`, the current CommitSet, and ExecutionLease.
2. If an active owner holds a valid lease, do not dispatch, restart, take over, or duplicate
   work. If the lease is expired, reconcile the owner and worker identity before takeover.
3. For an unknown side-effect outcome, perform read-only reconciliation and never replay
   generation, revision, pairing, adoption, or another non-idempotent action.
4. Reconcile the current claim with fresh configured gates and real code/test anchors before
   choosing a target.
5. Use these commands, derived from `server/pyproject.toml` and `ui/package.json`:
   - Python test: `uv run --frozen --project server pytest --basetemp .skillflow/tmp/pytest`
   - Python check: `uv run --frozen --project server ruff check server/src server/tests scripts`
   - UI test: `npm --prefix ui test -- --run --pool=threads`
   - UI check: `npm --prefix ui run typecheck`
   - UI build: `npm --prefix ui run build`
   - Benchmark: absent from the build configuration; do not invent one.
6. A missing runner, dependency, permission, or input is infrastructure evidence, not a pass.
   A completed non-zero validation remains a failure and blocks completion.

## State determination protocol

For the routed milestone or finding:

1. Read the claim only from `docs/IMPLEMENTATION_STATUS.md`.
2. Run the narrow affected gate, then the full configured gate set required by the plan.
3. Verify the plan task's code anchor resolves to current source and a regression test exists
   and actually runs.
4. Classify the three-way evidence:
   - `confirmed`: the claim, green gates, code anchor, and running regression agree.
   - `stale-claim`: the status claims completion but a gate fails or the regression is absent.
   - `ahead`: code and regression are green while the status does not yet record the outcome.
   - `assumption-rotted`: a referenced anchor or test no longer exists.
   - `expected-incomplete`: a downstream milestone is intentionally excluded until its
     prerequisite closes.
5. Output `<target>: <classification> because <gate evidence> + <code/test evidence>`.
   Do not persist from inside classification. An `ahead` result routes to a separate status
   write-back, followed by a fresh determination.

## Precise routing protocol

1. Work sequentially from the earliest non-confirmed prerequisite; never skip an open earlier
   milestone or mix downstream implementation into its candidate.
2. Write back `ahead` evidence before selecting another task. Treat `stale-claim` as incomplete;
   send `assumption-rotted` to plan correction instead of redoing code blindly.
3. Exclude expected-undeveloped milestones until all prerequisite gates close.
4. Before every interface change, decide whether the product surface is in development or
   released, then apply the stricter applicable compatibility and migration rule.
5. Authority precedence is `Storyforge > Writing MCP > PlotRail > candidate text`. Lower
   authorities may provide evidence or candidates but cannot overwrite higher authority,
   expand permissions, or turn recommendations into canon.
6. Unknown routes return a precise cannot-verify result unless the project contract explicitly
   mandates denial. Missing evidence never becomes pass.
7. Review-budget exhaustion cannot reset through renamed rounds, changed risk labels, refrozen
   candidates, or plan regeneration. Route open findings to an explicit remediation block:
   failing evidence, bounded repair, complete machine gates, and a new CommitSet. Then stop for
   human adjudication. Do not create another ordinary independent-review round without new authority.
8. This project skill cannot mutate SkillFlow's catalog, cannot grant permissions, and cannot
   install browser extensions, start external runtimes, publish, push, or widen Origins unless the
   approved project plan and current authorization explicitly permit that action.

## Fix discipline

1. For executable behavior, use strict TDD or a root-cause regression: write the smallest failing
   test, run it and confirm the intended failure, then implement the minimum change.
2. For documents, configuration, or generated protocol, record the repeatable pre-change gap and
   use verification-only evidence; do not claim TDD.
3. Run affected gates first and the required full gates after the focused repair. Keep commands,
   exit codes, warnings, omissions, and change digest parallel in TestEvidence.
4. Public tool, schema, error, persistence, authorization, or security changes require the
   corresponding contract/ADR update before commit.
5. Completion binds to current machine gates plus a real regression anchor, never documentation
   self-report. Update the unique status source only after the evidence is durable.

## Commit rules

- Commit points are independently rollback-able fixes, stable sub-gates, approved plan/protocol
  adjustments, milestone machine-gate completion, and milestone review receipts.
- Use the repository's observed conventional subject style such as `fix: ...`, `feat: ...`, or
  `docs: ...`; add a body when motivation, safety boundary, or verification is not obvious.
- Work on the current feature branch. Do not push, merge, rewrite user history, or force-update a
  remote without explicit authority.
- At a milestone boundary, freeze the exact repository SHAs and receipts in a CommitSet only after
  the worktree and gates represent the candidate being reviewed.
- Do not commit `%LOCALAPPDATA%` state, manuscripts, browser profiles, tokens, pairing codes,
  secrets, temporary test databases, `.dist/`, `.skillflow/`, or other ignored runtime evidence.

## Known boundaries

- Python is constrained by `server/pyproject.toml` to 3.12; the probed generation host used Python
  3.12.8, uv 0.12.3, Node 24.16.0, and npm 11.16.0. Re-probe after environment changes.
- On the probed Windows host, pytest's default user Temp root denied access, so use the repository
  `.skillflow/tmp` basetemp. Vitest's default fork pool returned `spawn UNKNOWN`, so use its thread
  pool. Treat either missing override as an infrastructure-path regression, not a product failure.
- There is no top-level aggregate gate and no configured benchmark. Use the declared Python and UI
  commands individually and do not fabricate missing scripts.
- Windows must remain logged in, unlocked, awake, with Codex running for unattended v1 behavior.
- The in-app Browser is attended diagnostics only. Dedicated Edge/browser-use, Storyforge, Writing
  MCP, and adoption are unavailable until their own milestone evidence closes.
- All durable project outputs remain `human_review_status=pending` until the user accepts or rejects
  them. Independent evidence and human acceptance remain distinct.
- Before any future push, check whether the remote is ahead. If unrelated histories require an
  explicit merge strategy, state which side wins for each conflicting file; never default to force.
